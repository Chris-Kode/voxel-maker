# glTF/GLB fixture corpus (tickets #41/#42, plan S16.8)

Checked-in byte-stable golden glTF/GLB exports used by
`packages/formats/src/gltf-fixtures.test.ts` to prove the export contract
(ADR-0011, `docs/format/gltf-v1.md`): units, axes, hierarchy, pivot
helper chains, mesh dedup, material mapping, deterministic naming, loss
reports, animation mapping, and byte determinism.

- `golden/cube.glb` + `golden/cube.gltf`: a 2x2x2 two-material cube on a
  translated node (the byte-stable golden; both containers must embed the
  same scene graph and buffer).
- `golden/hierarchy-pivot.glb`: a nested pivoted arm with a helper-node
  chain and a child node.
- `golden/lossy.glb`: transparent (BLEND) material, an exported
  single-keyframe Clip, a joint, document/node metadata, and an empty
  volume, all reported as losses.
- `golden/animated.glb`: a pivoted arm with a child hand and one loop
  Clip mapping to a glTF animation — linear rotation on the pivot
  helper, step translation on the chain head, baked smoothstep scale on
  the child, plus a rotation-limit constraint reported as a loss.
- `golden/*.document.json` / `golden/*.volumes.json`: the retained
  canonical document and volume entries needed to rebuild the exact
  bytes; the corpus test fails if rebuilding no longer reproduces the
  checked-in files.
- `corpus.json`: machine-readable index with byte lengths, recorded
  structure counts (nodes, meshes, materials, accessors, faces, voxels,
  animations, channels, samplers), and the recorded animation sample
  data that the independent GLB reader must reproduce.

Every fixture is generated by `scripts/generate-gltf-fixtures.mjs`, which
self-checks each file against preflight/plan/encode before writing, so the
corpus can never drift from the exporter. Regenerate after a build with:

```sh
pnpm build
node scripts/generate-gltf-fixtures.mjs
```
